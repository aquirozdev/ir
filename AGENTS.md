# Repository instructions

- Treat SIR as an experimental business-application representation.
- Distinguish implemented behavior, proposals and measured results in every document.
- Keep AST, schema, examples and documentation aligned.
- Commands must fail closed and roll back effects on policy/precondition/invariant failures.
- Never use final evaluation tests as generation feedback, training labels or rewards.
- Do not add arbitrary shell, source execution or network capabilities to SIR.
- Run formatting, workspace tests, Clippy and repository checks for relevant changes.
- Do not invent benchmark numbers or claim general frontier equivalence.
